# plan_T7: 가입, 첫 사용 동의, 「이대로 입히기」, 골드 원장

> 로드맵: `docs/roadmap.md` 「T7」 · 작성 2026-11-25 · 상태: 진행 중

## 목표

가입하고 동의한 사용자가 완성 룩 사진을 받게 하고, 실패하면 쓴 무료 장이나 골드를 돌려준다.

## DoD (로드맵 원문, 번호는 이 파일에서 붙임)

- [ ] D1 [웹화면] 가입 전에 「이대로 입히기」 를 누르면 가입 시트가 먼저 열린다. 시트를 닫아도 무대의 코디가 남는다. (S5-1)
- [ ] D2 [DB] 가입하면 `users` 에 행이 하나 생긴다. 로그아웃 뒤 같은 로그인으로 들어와도 행이 늘지 않는다. (S5-2)
- [ ] D3 [웹화면] 가입 뒤 첫 「이대로 입히기」 에서 「완성 룩 만들기」 시트보다 동의 화면이 먼저 뜬다. (S5-4)
- [ ] D4 [DB] 동의하면 `consents` 에 `text_version` 과 `agreed_at` 이 채워진 행이 하나 생긴다. (S5-6)

## 확인한 사실 (2026-11-25 실측)

실측 파일은 세션 스크래치 `t7/` 의 다섯(와이어프레임 둘, PRD, 서버 문서, 저장소 지도)과 빈칸 점검 `gaps.md` 다.

- 와이어프레임 v26 의 무대 단추는 체리색 「이대로 입히기」 와 작은 글자 「무료 2장 남음」 이다. 무료 장이 0 이면 「이대로 입히기 4골드」 다.
- 와이어프레임의 「이대로 입히기」 는 가입을 묻지 않는다. 로드맵 DoD D1 과 로드맵 v4 는 가입 시트를 먼저 연다. DoD 를 따른다.
- 가입 시트 글자(제목 「골드를 쓰려면 가입해요」, 「닫아도 지금 코디는 이 휴대폰에 그대로 남아요.」)는 와이어프레임 꾸미기 구매 흐름에 있다.
- 첫 사용 동의 화면, 동의 철회 줄, 로그아웃 확인 시트는 와이어프레임과 PRD 어디에도 없다. 이 plan 이 제안 문구로 새로 그린다(화면 문구 절).
- 만드는 중 단계 글자: 「옷을 입히고 있어요」(33%) → 「앞모습을 그리고 있어요」(67%) → 「다 됐어요」(100%). 맨 아래 「화면을 닫아도 계속 만들어요. 다 되면 결과를 보여 드려요.」
- 결과 화면(「✦ AI 생성」, 「룩북에 저장했어요. 나만 볼 수 있어요」), 「저장하지 않고 나갈까요?」 시트, 「만들지 못했어요.」 화면은 와이어프레임 v24 데모 덧층에 있다.
- 「내 골드」 는 마이 카드에서 들어간다. 내역 줄 예시는 「완성 룩 1장 -4골드」 와 「완성 룩 환불 +4골드」 다.
- 즐겨찾기: 별은 룩 사진 오른쪽 위, 알림 「즐겨찾기에 넣었어요」 「즐겨찾기에서 뺐어요」, 칩 「전체 N」 「즐겨찾기만 N」.
- 「다른 룩북에 넣기」: 고르기 전 두 단추 회색(누르면 「넣을 룩북을 먼저 골라 주세요」), 복사 알림 「「겨울 여행」에도 넣었어요」, 옮기기 알림과 「되돌리기」.
- 와이어프레임의 「새 룩북 만들기」 는 만든 뒤 그 룩을 새 룩북으로 바로 옮긴다. DoD D14 는 만든 뒤 「복사해서 넣기」 를 누른다. DoD 를 따른다.
- 서버 문서(스키마 v1, 시퀀스 v1, 기술 검토 v3)는 Supabase 전제로 쓰였다. 11/24 결정대로 Postgres 와 API 서버로 바꿔 읽는다.
- 저장소 `docs/roadmap.md` 보다 26분 늦은 로드맵 v4 HTML 이 있다(DoD 24줄, 작업은 따로 도는 worker). 저장소에 옮길지는 기획자 결정 대기(PR 8 세션)다.
- API 서버는 Node 가 TypeScript 를 그대로 돌려 `@nuno/*` 패키지를 import 하지 못한다(`ERR_UNSUPPORTED_DIR_IMPORT`).
- main 의 DB 시험 `apps/api/src/db/api-db.db.test.ts` 가 `/v1/health` 의 판 번호를 1 로 박아 두었다. 서버 판 0002 를 더하면 실패한다. 훅이 이 파일 편집을 막는다.

## 설계 결정

1. 서버 업무 코드는 `apps/api/src/<컨텍스트>/` 에 둔다(account, gold, generation, lookbook).
   - 까닭: 서버가 패키지를 import 하려면 실행기나 빌드 의존성이 든다. 골드와 작업 상태 규칙은 거의 DB 함수에 있다.
   - 버린 안: `packages/gold`, `packages/account` 를 만들고 tsx 를 들인다. 앱은 골드 규칙을 쓰지 않아 나눌 값이 작다.
   - 루트 `AGENTS.md` 표의 두 줄을 이 자리로 고친다.
2. 로그인은 API 서버가 직접 만든 세션 토큰이다.
   - 토큰은 32바이트 난수(base64url)다. DB 에는 SHA-256 만 둔다. 만료는 90일(코드 상수 `SESSION_DAYS`).
   - 표: `auth_identities`(provider, subject → user_id), `auth_sessions`(token_hash, user_id, expires_at, revoked_at).
   - Apple: `POST /v1/auth/apple` 이 신원 토큰을 Apple 공개 키(JWKS)로 확인한다. `iss`, `aud`(번들 ID), `exp`, nonce 를 본다.
   - 인가 코드를 refresh token 으로 바꿔 AES-256-GCM 으로 암호화해 `apple_credentials` 에 적는다. 키는 환경 변수다.
   - Apple 설정 환경 변수가 없으면 이 주소는 503 `apple_not_configured` 를 낸다.
   - 서명 확인과 client secret 서명은 Node `crypto` 로 한다. 새 의존성은 없다.
   - 버린 안: Better Auth(표와 판 옮기기를 따로 가져와 우리 판 체계와 겹친다), `jose`(Node `crypto` 로 충분하다).
3. 개발 전용 주소는 `/v1/dev/` 아래에 모으고 `NUNO_DEV_ROUTES=1` 일 때만 단다. 값이 없으면 404 다(D18).
   - `POST /v1/dev/login {subject}`: 시험용 로그인. 같은 subject 면 같은 사용자다(D2).
   - `POST /v1/dev/gold {amount}`: 시험용 골드 한 번(멱등 키 `test_grant:<사용자 ID>`, 줄 이름 「시험용 골드」).
   - `POST /v1/dev/provider {mode, delayMs}`: 가짜 공급사를 `succeed`, `refuse`, `hang` 으로 바꾼다.
   - 앱의 「시험 계정으로 계속하기」 단추는 웹 개발 빌드(`__DEV__`)에서만 보인다. subject 는 브라우저마다 한 번 만들어 둔다.
4. 동의: `consents(kind, text_version, agreed_at, withdrawn_at)`. kind 는 `generation_transfer` 하나다.
   - 최신 문구 판은 서버 상수 `CONSENT_TEXT_VERSION` 이다. 앱은 서버가 준 판 번호를 그대로 보낸다. 다르면 409.
   - 동의 화면의 공급사 이름과 나라는 `provider_configs` 의 쓰는 줄에서 읽는다. 다시 동의하면 새 행을 더한다.
5. 골드는 복식 원장이다(스키마 v1 3.4 그대로).
   - 표: `gold_accounts`(사용자 넷 `trial`, `free_gold`, `paid_gold`, `hold`, 시스템 `promo_grant`, `promo_used`, `revenue`), `gold_transactions`, `gold_entries`, `gold_holds`.
   - `gold_entries` 와 `gold_transactions` 는 고치기와 지우기를 트리거로 막는다. 거래 합 0 은 지연 제약 트리거로 커밋 때 본다.
   - 묶기는 `trial` → `free_gold` → `paid_gold` 순서로 4 를 모은다. 계정 둘에서 섞어 모을 수 있다. 풀기는 나온 계정으로 그대로 돌려준다.
   - 확정은 무상 몫을 `promo_used`, 유상 몫을 `revenue` 로 보낸다. 무료 장 수는 `trial` 잔액 나누기 4 다.
   - 가입 때 `trial:<사용자 ID>` 로 8골드(무료 2장)를 한 번 넣는다. 한 계정의 무료 접수는 한국 시간 하루 4건까지다.
6. 작업 상태와 골드는 DB 함수로만 바뀐다. 함수는 `SECURITY DEFINER`, `search_path = public, pg_temp`, `nuno_api` 에 하나씩 GRANT.
   - 함수 이름: `nuno_sign_in`, `nuno_session_user`, `nuno_sign_out`, `nuno_grant_test_gold`, `nuno_submit_job`, `nuno_claim_job`,
     `nuno_start_attempt`, `nuno_finish_attempt`, `nuno_job_checking`, `nuno_job_retry`, `nuno_job_succeed`, `nuno_job_fail`,
     `nuno_sweep_jobs`, `nuno_discard_result`, `nuno_keep_result`.
   - 업무 시각은 인자 `p_now` 로 받는다. 시험이 시각을 앞으로 돌려 선점 기한을 넘긴다.
   - 접수 함수 하나가 멱등 확인, 계정 상태, 동의, 스위치, 무료 하루 한도, 잔액 잠금(`FOR UPDATE`), 묶기, 작업 행을 한 트랜잭션에 한다.
   - 접수 거절은 `error_code` 로 돌려준다: `consent_required`, `insufficient_gold`, `switch_off`, `trial_daily_limit`, `request_mismatch`.
   - 같은 요청 ID 를 다시 보내면 처음 작업 ID 와 상태를 그대로 준다. 같은 ID 에 다른 입력이면 `request_mismatch`.
   - `nuno_api` 는 골드 표와 작업 표에 SELECT 만 가진다. INSERT, UPDATE, DELETE 는 없다(D12).
7. 작업 실행은 API 서버와 따로 도는 worker 프로세스다(로드맵 v4). 같은 코드에서 `pnpm --filter api worker` 로 띄운다.
   - worker 는 1초마다 `nuno_claim_job` 으로 접수 작업 하나를 선점한다(`FOR UPDATE SKIP LOCKED`, 선점 기한 = 공급사 시한 150초 + 30초).
   - 차례: 시도 행 → 공급사 → 결과를 `gen30/` 에 저장 → `checking` → 출력 검사 → 완료와 확정. 검사에서 처음 떨어지면 한 번만 다시 만든다.
   - 공급사 거절, 시한 초과, 오류는 다시 만들지 않고 실패와 풀기다.
   - 예약 작업은 worker 가 60초마다 `nuno_sweep_jobs` 를 부른다. 선점 기한을 넘긴 생성 중과 검사 중 작업을 실패로 바꾸고 푼다.
   - 늦게 온 결과는 `lease_token` 이 맞지 않아 상태와 골드를 바꾸지 못한다.
   - 버린 안: API 안 실행(배포 때 요청이 끊기면 작업이 멈춘다), 작업 큐 서비스(지금 규모에 비해 무겁다). 돌림 줄은 로드맵대로다.
8. 결과 사진 저장은 포트 `ResultStore` 다. 이번에는 로컬 디스크 어댑터와 API 서명 주소만 만든다.
   - 서명 주소: `/v1/files/<키>?exp=<초>&sig=<HMAC-SHA256>`. 서명이 틀리거나 기한이 지나면 403, 파일이 없으면 404 다.
   - 결과 보기 기한은 10분(코드 상수). 키는 `gen30/<사용자 ID>/<작업 ID>.jpg`, 저장하면 `u/<사용자 ID>/looks/<결과 ID>.jpg` 로 복사한다.
   - 「나가기」 는 `nuno_discard_result` 로 결과를 지움 상태로 적고 파일을 지운다. 그래서 적어 둔 서명 주소가 404 다(D9).
   - R2 어댑터는 버킷과 키가 오면 같은 포트로 더한다. 그때 D9 를 R2 로 한 번 더 판정한다.
9. 출력 검사는 포트 `ImageCheck` 다. 이번에는 가짜(늘 통과, 시험에서 첫 장만 떨어뜨리기)만 둔다. 검사 회사가 정해지면 더한다.
10. 룩북(서버): `lookbooks(id, user_id, title, sort_order, created_at)`, `looks(id, user_id, lookbook_id NULL, result_id, is_favorite, worn_items, saved_at)`.
    - `lookbook_id` 가 빈 줄은 「모든 룩」 에만 보인다. 저장 연타에도 한 줄(고유 색인 `(user_id, lookbook_id, result_id) NULLS NOT DISTINCT`).
    - 별은 같은 사용자의 같은 결과를 가리키는 줄을 함께 바꾼다. 「즐겨찾기만 N」 은 지금 룩북 안에서 센다.
    - 복사는 같은 결과로 줄 하나 더, 옮기기와 되돌리기는 그 줄의 `lookbook_id` 를 바꾼다. 룩북 이름은 12자까지, 같은 이름도 받는다.
    - 룩북 표와 룩 표는 업무 상태가 아니라서 `nuno_api` 에 사용자 ID 조건을 건 DML 을 준다. 결과 파일 상태는 함수로만 바꾼다.
    - 기기 견본 룩(온보딩 「첫 코디」)은 「모든 룩」 에 함께 보이고 별과 「다른 룩북에 넣기」 는 숨긴다.

## 리뷰 반영 (2026-11-25, 관점 일곱, 지적 50건 가운데 반박 검증을 통과한 28건)

같은 뜻의 지적은 묶었다. 기각 22건은 이미 plan 에 있거나 고칠 값이 작았다.

1. CORS: API 가 `NUNO_WEB_ORIGINS`(쉼표 목록) 출처만 `hono/cors` 로 받는다. 값이 없으면 CORS 머리글을 내지 않는다. 머리글은 Authorization, Content-Type 만 연다. 반영.
2. 가짜 공급사 모드는 API 메모리가 아니라 DB 의 사용자별 줄이다. 반영.
   - 판 0003 의 `dev_provider_modes(user_id, mode, delay_ms, fail_check_once)` 는 `nuno_dev_set_provider_mode` 로만 바꾼다.
   - worker 는 `NUNO_DEV_ROUTES=1` 일 때만 작업마다 그 사용자의 줄을 읽는다. 줄이 없으면 `succeed`, 지연 0 이다.
   - `createFakeProvider` 에 지연 인자를 더한다. e2e 는 시험마다 새 subject 로 로그인해 모드가 섞이지 않는다. `hang` 은 DB 시험에서만 쓴다.
   - 시험용 로그인의 provider 는 코드 상수 `dev` 로 고정한다. Apple 신원과 섞이지 않는다.
3. D16: 판 0002 에 `devices(id, user_id, push_token 고유, platform, notify_looks, created_at, last_seen_at)` 를 둔다. 반영.
   - `POST /v1/devices` 로 토큰을 등록한다. worker 는 완료와 실패 뒤 포트 `PushSender` 를 부른다. 지금 어댑터는 로그만 남긴다.
   - 앱은 작업 ID 로 결과를 여는 라우트 `generate/[jobId]` 하나를 둔다. 무대 알림 「보기」 와 푸시가 함께 쓴다.
   - 권한 묻기, Expo 푸시 어댑터, Apple 단추, 실기기 판정은 환경이 오면 PR E 로 한다.
4. 만드는 중 단계 글자는 작업 상태로 고른다. `queued` 「옷을 입히고 있어요」 33%, `generating` 「앞모습을 그리고 있어요」 67%, `checking` 과 `succeeded` 「다 됐어요」 100%. 반영.
5. 잠금 순서: 골드와 작업 함수는 모두 그 사용자의 `users` 행을 맨 먼저 `FOR UPDATE` 로 잠근다. 반영.
   - 잠근 뒤 멱등 확인, 하루 무료 한도, 잔액을 본다. 작업 행을 먼저 넣고 그 ID 로 묶는다.
   - DB 시험은 연결 여러 개로 같은 요청 ID 10건을 동시에 보내고, 모두 같은 작업 ID 를 받는지 본다.
6. 선점: worker 가 부르는 함수는 `status`, `lease_token`, `lease_until > p_now` 셋이 맞아야 쓴다. `nuno_job_retry` 는 선점 기한을 다시 늘린다. 반영.
   - DB 시험: 시각을 기한 너머로 돌려 정리한 뒤 같은 토큰으로 완료를 부르면 작업 상태와 묶음 잔액이 그대로다.
7. 남의 행: 사용자 ID 는 세션에서만 얻고 요청 본문에서 받지 않는다. 반영.
   - `lookbooks` 에 `UNIQUE (user_id, id)`, `looks` 는 `(user_id, lookbook_id)` 와 `(user_id, result_id)` 복합 FK 를 건다.
   - 결과와 작업 함수는 `p_user_id` 를 받고 주인이 다르면 없는 것으로 답한다. DB 시험이 사용자 A 세션으로 B 의 작업 조회, 결과 저장, 룩북 옮기기를 불러 막히는지 본다.
8. 앱 쪽 업무 규칙 자리: `pnpm new:context generation` 으로 `packages/generation` 을 만든다. 반영.
   - application: 기기 판 7 `generation_requests` 표와 옮기기 단계. domain: 무대 단추 글자, 단계 고르기, 거절 코드에 따른 다음 화면 판정.

11. 작업 감시는 앱 최상위 한 곳이다. 반영.
    - 앱을 켤 때와 앞으로 올 때 기기 `generation_requests` 의 끝나지 않은 작업을 2초마다 묻는다.

12. 로그아웃: `nuno_sign_out` → 기기 세션 토큰 지우기 → 기기 `generation_requests` 모두 지우기 → 화면이 들고 있던 서버 값 비우기. 옷장, 「내 코디」, 견본 룩은 남긴다. 다른 계정으로 들어올 때도 같다. 반영.

- PR C 는 앱 의존성 `expo-secure-store` 하나만 들였다. Apple 단추(`expo-apple-authentication`)와 푸시 권한은 PR E 로 미룬다.
- 기기 판 7 `generation_requests` 에 보낸 입력 목록 칸 `manifest` 를 더했다. 결과 화면의 입은 옷과 만드는 중 그림이 이 값을 쓴다.
- 결과 화면의 견본 옷은 옷장 칸이 없어 칸 이름을 「견본 옷」 으로 적는다. 접수 입력과 저장의 칸 값은 `null` 이다.
- 마이의 「설정」 은 와이어프레임 v26 처럼 머리 오른쪽 톱니(이름 「설정」)로 둔다.
- 접수 거절 알림 셋은 이 plan 이 새로 쓴 글이다: 「지금은 완성 룩을 만들 수 없어요. 잠시 뒤에 다시 해 주세요」(스위치 꺼짐), 「오늘은 무료로 더 만들 수 없어요. 내일 다시 해 주세요」(무료 하루 한도), 「이 계정으로는 지금 만들 수 없어요」(정지 계정).
- 동의 문구의 보관 일수 N 은 앱 문구 판 1 에 든 상수 `PROVIDER_RETENTION_DAYS`(30일)다. 서버는 공급사 이름과 나라만 준다.
- 「내 골드」 내역이 비면 「아직 사용 내역이 없어요」 를 보인다(와이어프레임에 없는 글).
