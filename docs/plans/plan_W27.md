# plan_W27: 와이어프레임 v27 에 맞춰 이미 만든 화면 고치기

> 기준: 와이어프레임 v27 변경기록(2026-11-25, 기획자 결정 2026-11-26 포함)과 GPT UI 리뷰 개선 시안 v2. 작성 2026-11-25, 재확인 2026-11-26. 상태: DoD 판정 끝(2026-11-27), 기획자 승인 항목 반영(2026-11-27)

## 목표

이미 만든 홈, 코디, 옷장, 옷 넣기, 완성 룩 화면을 와이어프레임 v27 과 같은 글과 배치로 고친다.
기획자가 2026-11-25 에 정한 네 가지(R1~R4)를 먼저 넣는다.

- R1: 홈 시트의 「최근 저장한 룩」 이나 「최근 추가한 옷」 칸이 비면, 빈 안내 대신 추천 코디 카드를 가로로 보인다.
- R2: 「완성 룩 만들기」 시트와 만드는 중 화면에서 「앞 1장」, 「앞모습」 같은 장 종류 표기를 모두 뺀다.
- R3: 시트, 골드 확인, 만드는 중 화면, 「내 골드」 에서 「만들지 못하면 …돌려드려요」 를 지운다. 실패 화면의 반환 표시는 남긴다.
- R4: 「이번에는 첫 체험 무료 2장 중 1장을 써요」 대신, 가격 칸에 줄 그은 「4골드」 와 「무료」, 아래 줄 「무료로 만들 수 있는 사진이 2장 남았어요」 를 보인다.

## 확인한 사실 (2026-11-25 실측)

- main 에 머지된 것: T1~T5, T7 앱 흐름(PR 19~24). T6 은 진행 중이고 T8, T9 는 대기다.
- 앱 화면 코드는 `apps/mobile` 이다. 화면 글자 함수는 `packages/generation/src/domain/generation.ts` 에 있다.
- 기존 단위 시험 `packages/generation/src/domain/generation.test.ts` 가 지금 글자를 박아 두었다.
  - `progressStep("generating")` 의 「앞모습을 그리고 있어요」, `stagePriceLabel(0)` 의 「4골드」, `goldConfirmCopy` 의 「24 → 20골드」.
  - 이 파일은 PreToolUse 훅이 고치기를 막는다. 그래서 이 함수들은 그대로 두고 새 함수를 더한다.
- e2e 준비 시험 `e2e/onboarding.setup.ts` 가 트윈 고르기의 「닫기」(X)와 처음 둘러보기의 「닫기」 를 눌렀다.
  - 기획자 승인(2026-11-27) 뒤 01-1 과 01-5 를 v27 로 바꾸면서 준비 시험도 「건너뛰기」 를 누르게 고쳤다.
- R1 자료는 `@nuno/outfit` 의 `RECOMMENDED_LOOKS` 다. 코디 탭 「추천 코디」 카드와 같은 자료이고, 착장 사진은 `lookPhotoOf` 로 찾는다.
- 앱 작업 결과의 실패 원인은 `JobView.failureCode` 로 온다. `provider_refused` 와 `check_failed` 는 안전 기준, 나머지는 시스템 오류로 읽는다.
  - `check_failed` 는 결과 사진이 서버 자체 안전 검사를 두 번 통과하지 못한 실패다(`apps/api/src/generation/worker.ts`). 기획자 확인 10번.
- 옷 정보 단계의 소유 기본값은 이미 넣기를 시작한 칸(`from`)을 따른다. 고칠 것이 없다.
- 홈 빈 칸 설명은 기획자 결정(2026-11-26)대로 「다른 사람들의 코디에서 골랐어요」 다. 카드 배지는 「NUNO 추천」 그대로다.
- 완성 룩 결과의 입은 옷 출처는 기획자 결정(2026-11-26)대로 「내 옷장」 과 「담은 옷」 이다.

## 설계 결정

1. 이미 있는 글자 함수는 지우지 않고, v27 글자는 새 함수로 더한다.
   - 새 함수: 무대 단추 옆 글 「무료 N장 남음」, 「1장 4골드」. 시트 세 상태(무료, 골드, 골드 부족)의 가격 칸과 아래 줄. 만드는 중 글. 실패 화면 글(원인과 낸 것 네 경우).
   - 새 시험 파일 `packages/generation/src/domain/make-look-copy.test.ts` 에서 본다.
   - 쓰지 않게 되는 `makeSheetCopy` 와 `failureCopy` 는 박아 둔 시험이 없어 지웠다.
   - `goldConfirmCopy`, `payWithFor`, `stagePriceLabel`, `progressStep` 은 main 의 `generation.test.ts` 가 박아 두어 남긴다.
   - 다시 쓰지 않게 패키지 공개 면에서는 뺐다. 시험 줄과 함께 지우는 일은 기획자 확인 9번이다.
2. 「완성 룩 만들기」 시트 하나가 무료, 골드, 골드 부족 세 상태를 그린다. 「완성 룩 1장 만들기」 골드 확인 시트는 쓰지 않는다.
   - 골드 상태의 「4골드 사용」 은 그 자리에서 골드로 접수한다.
   - 골드 부족 상태는 세 줄 표만 보인다. 「골드 충전」 과 충전 안내 줄은 충전(T8)이 생길 때 더한다. 시트는 X 로 닫는다.
   - 무료 장이 남았는데 오늘 무료 한도에 닿았으면 골드 상태 위에 「오늘은 무료로 더 만들 수 없어요」 한 줄을 둔다. v27 에 없는 줄이라 기획자 확인에 적는다.
3. R1 카드는 홈 전용 새 부품 `src/ui/home-reco-strip.tsx` 가 그린다. 코디 탭 카드(`outfit-card.tsx`)는 코디 묶음이 따로 고친다.
   - 카드는 104×139, 위쪽 맞춤 착장 사진, 왼쪽 아래 「NUNO 추천」 배지, 아래 두 줄 코디 이름이다.
   - 무대 트윈의 기본 코디(추천 목록 첫째)는 뺀다.
   - 카드를 누르면 `changeOutfit` 으로 그 코디를 입히고 피팅룸 코디 탭을 연다. 「…코디로 바꿨어요」 알림과 「되돌리기」 를 띄운다.
4. 팔레트는 새 공용 파일을 만들지 않는다. 묶음마다 자기 파일 안의 옛 값을 아래 표대로 바꾼다. 남은 파일은 공통 묶음이 맡는다.

| --- | --- | --- |
| `#76736C` | `#5F5C56` | 설명, 개수, 날짜 글자 |
| `#FCFCFC` | `#FCFBFA` | 화면 바탕 |

5. 기존 시험 파일은 처음에는 고치지 않았다. v27 로 깨지는 기대값은 아래 「기존 시험 기대값」 에 모으고, 새 동작은 새 e2e 파일로 본다.
   - 기획자가 2026-11-27 에 v27 값으로 고치기를 승인해 e2e 기대값을 고쳤다. `*.test.ts` 단위 시험은 그대로 둔다.
6. 묶음 B 가 `useGenerateFlow` 에 옷 칸을 올린 상태용 작은 「이대로 입히기」(`compactButton`)를 더한다. 묶음 C 는 그 값을 받아 그린다. B 를 먼저 한다.
