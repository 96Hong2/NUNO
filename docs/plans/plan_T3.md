# plan_T3: 옷 사진 넣기와 「내 옷」, 「담은 옷」 두 칸 옷장

> 로드맵: `docs/roadmap.md` 「T3」 · 작성 2026-11-25 · 상태: 진행 중

## 목표

사용자가 옷 사진을 넣어 배경을 지우고, 가진 옷과 사고 싶은 옷을 두 칸에 나눠 모으게 한다.

## DoD (로드맵 원문, 번호는 이 파일에서 붙임)

- [x] D1 [웹화면] 피팅룸 「옷장」 에 「내 옷」, 「담은 옷」 두 칸이 있고 칸마다 옷 수가 보인다. 고른 칸의 수는 체리색이다. (C22)
- [x] D2 [웹화면] 「담은 옷」 이 0벌이면 「아직 담은 옷이 없어요」 가 보인다. 「스토어 둘러보기」 와 「옷 담으러 가기」 는 없다(C29 와 다름, S2-14). (C29)
- [x] D3 [웹화면] 「내 옷」 이 0벌이면 「아직 넣은 옷이 없어요」 와 「옷 추가」 가 보인다. (C29)
- [x] D4 [웹화면] 「옷 추가」 를 누르면 「사진 찍기」, 「앨범에서 고르기」 가 든 「옷을 어떻게 넣을까요?」 시트가 열린다. (C31)
- [x] D5 [웹화면] 앨범 사진을 고르면 미리 만든 누끼 그림이 「배경을 지웠어요」 에 뜬다. 도구 넷 「지우기」, 「되살리기」, 「자르기」, 「돌리기」 가 보인다. (C32, S2-2)
- [x] D6 [웹화면] 「이 옷, 가지고 있나요?」 답에 따라 마지막 단추가 「담은 옷에 담기」 나 「내 옷에 담기」 로 바뀐다. 담은 뒤 알림의 「옷장에서 보기」 를 누르면 그 옷이 든 칸이 열린다. (C33, C28)
- [x] D7 [웹화면] 「어떤 옷인가요?」 에서 브랜드를 적어 담은 「담은 옷」 카드에 「담은 옷」 알약과 그 브랜드가 보인다. (C25)
- [x] D8 [웹화면] 「내 옷」 세 벌과 「담은 옷」 두 벌의 별을 누르면 「내 옷」 칩은 「즐겨찾기 3」, 「담은 옷」 칩은 「즐겨찾기 2」 다. 칩을 누르면 그 칸의 별 옷만 보인다. (C24)
- [x] D9 [웹화면] 「여러 벌 옮기기」 로 두 벌을 고르고 「내 옷으로 옮기기 2」 를 누르면 두 벌이 「내 옷」 칸으로 간다. 옷 상세 왼쪽 단추가 「내 옷에 있어요」 로 바뀐다. (C26, C53)
- [x] D10 [DB] 마지막 담기 단추를 다섯 번 연타해도 `garments` 행은 1개다. `garment_sources.method` 가 `album` 이다. (S2-10, S2-15)
- [x] D11 [웹화면] 옷 13벌을 넣고 홈 「최근 넣은 옷」 탭을 열면 3열로 12벌이 보인다. 마지막에 넣은 옷이 왼쪽 위에 있다. (C11)
- [x] D12 [웹화면] 같은 탭에서 「담은 옷」 칸 옷에 「담은 옷」 배지가 붙고, 탭 머리에 「내 옷 N벌, 담은 옷 N벌」 이 보인다. (C11)
- [ ] D13 [iOS] 아이폰에서 Apple Vision 누끼가 뜬다. 사람이 든 사진은 「옷만 보이도록 잘라 주세요」 가 뜨고, 저장한 그림에 위치 정보가 없다. (S2-3, S2-5, S2-11)
- [ ] D14 [iOS] 누끼 30장에서 손보지 않고 쓸 수 있는 비율, 손보기 시간, 100벌 용량이 관문 기록표에 있다. (G2-7)
- [x] D15 [웹화면] 그 비율이 통과선(결정 D25)에 못 미치면 「자르기」 와 붓 손보기가 기본 흐름에 있다. 옷만 나온 사진 안내도 보인다.

D15 는 D14 결과와 상관없이 웹 흐름에서 판정한다. 「자르기」 와 붓 손보기는 2 / 4 화면에 늘 있고, 안내는 「사진 찍기」 화면과 시트 설명 줄에 늘 보인다.

## 확인한 사실 (2026-11-25)

- 와이어프레임 v26 을 브라우저로 눌러 옷장, 옷 넣기 네 단계, 옷 상세, 홈 「최근 넣은 옷」 을 실측했다. 기획 문서끼리 다르면 로드맵 DoD 와 개발 계획 v3 를 따른다.
- 종류는 아우터, 상의, 하의, 신발, 가방, 액세서리 여섯이다. 색 칩은 블랙, 화이트, 그레이, 베이지, 브라운, 네이비, 레드, 그린 여덟이다. 계절은 넷, 사이즈 표기는 XS~XL 과 FREE 다.
- 옷 치수 칸은 종류마다 다르다: 상의와 아우터는 총장, 어깨너비, 가슴단면, 소매길이. 하의는 총장, 허리단면, 엉덩이단면, 밑단단면. 신발은 발길이(mm), 굽 높이. 가방과 액세서리는 가로, 세로, 끈 길이.
- 4 / 4 크기는 5%씩 70~140%, 위치는 2%씩 위아래 12칸이다. 2 / 4 붓 크기는 작게, 보통(처음), 크게다. 자르기를 처음 켜면 가장자리에서 8% 안쪽 네모다.
- 결정 D33: 기기는 색만 미리 고르고, 이름은 색과 종류로 채운다. 옷 벌 수에 한도가 없다(시트 아래는 「내 옷 N벌, 담은 옷 N벌」).
- S2-14: 「깔끔하게 정리하기」, 「옷 담으러 가기」, 「스토어 둘러보기」, 담아 온 곳 거르기 칩은 보이지 않는다.
- `e2e/tabs.spec.ts` 는 피팅룸 칸마다 본문 첫 제목(aria-level 2)이 칸 이름이기를 기대한다. 옷장 화면은 화면 읽기 프로그램용 제목 「옷장」 을 둔다.
- `expo-image-picker` 웹은 고른 파일을 blob 주소로 그대로 준다. 그래서 파일 해시로 견본 사진을 알아볼 수 있다.

## 와이어프레임과 다르게 둔 곳

- 하단 탭(홈, 피팅룸, 마이)과 피팅룸 네 칸, 「스토어 둘러보기」, 「옷 담으러 가기」, 「링크로 넣기」, 「깔끔하게 정리하기」, 담아 온 곳 거르기: 로드맵 T1, S2-14 대로 없다.
- 「안 입은 옷 N」 칩, 카드의 「N번 입었어요」, 「처음 올린 사람」: 입은 횟수와 올린 사람 기록이 첫 판에 없다(스키마 「입은 횟수 열은 두지 않는다」).
- 「다른 사람도 입어 볼 수 있게 두기」 와 「하린의 가상 치수」, 「트윈과 견주기」: 공유와 트윈 치수 막대가 생기는 T9 에서 본다.

- 웹 그림 저장을 IndexedDB 대신 OPFS 로 했다. 기기 DB 와 같은 브라우저 저장소이고 경로 규칙이 아이폰과 같다.
- 색 미리 고르기를 RGB 거리에서 Lab 거리로 바꿨다(견본 실측).
- 옷 상세에 「내가 넣은 사이즈와 치수」 와 「고치기」(치수 고치기)를 더했다. 와이어프레임 12-3 절에 있다.
